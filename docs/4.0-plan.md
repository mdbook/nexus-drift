# Version 4 — Interactivity Pass

## Context

Nexus Drift through 3.1.4 is a fully autonomous idle-sim: `stepAutobuy()` buys upgrades on a ~30-tick cadence ([src/game/subsystems/autobuy.ts:146](src/game/subsystems/autobuy.ts)), `chooseWorkerTarget()` picks tasks with no player input ([src/game/ai/workerTargeting.ts](src/game/ai/workerTargeting.ts)), and `stepCity` passively heals/produces energy ([src/game/subsystems/economy.ts:52](src/game/subsystems/economy.ts)). Player interactivity today is only cosmetic / achievement-hunting: clicking tourists, corpses, projectiles, anomalies, event chips — all routed through helpers in [src/game/achievements.ts:648](src/game/achievements.ts).

Version 4 flips the frame: the player is now the city's operator. They should be able to **buy upgrades themselves**, **nudge workers toward specific nodes/threats**, and have the game surface enough state to make those decisions meaningfully. Autobuy stays, but as an opt-in fallback so the existing idle-sim experience is still playable unchanged. This is a **major release (4.0)** for identity reasons — the game's genre changes — but it must **not break saves**; loaded 3.x saves should come up with autobuy-all enabled so returning players see continuity.

## Scope summary

**In scope for 4.0:**

1. Manual upgrade purchases with per-upgrade auto toggles (autobuy-as-fallback).
2. Soft click-to-suggest worker guidance (nudge, not hard assignment).
3. HUD affordances so purchases and suggestions are discoverable.
4. Onboarding surface: a first-run hint overlay and an "Idle Mode" quick-toggle for players who just want the old experience.

**Explicitly out of scope** (per user clarification):

- No control over enemies, wave balancer, or event spawns.
- No new city abilities / EMP / repair pulses.
- No hard worker assignment — AI stays authoritative under threat.

## 1. Interactable / controllable elements

| Element                                   | New interaction                                                                                      | Authority                                                                 |
| ----------------------------------------- | ---------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| Upgrade tiles (sidebar)                   | **Click to buy** when affordable; per-tile Auto toggle.                                              | Player-first; autobuy only when Auto is on.                               |
| Global "Auto: All / None / Custom" toggle | Top-of-upgrade-panel master switch.                                                                  | Player. Default ON for loaded 3.x saves, OFF for fresh 4.0 saves.         |
| Resource nodes (field)                    | **Click to suggest** — nearest eligible idle worker retargets here if path is safe.                  | Soft: worker AI can reject under threat.                                  |
| Enemies (field)                           | **Click to flag priority** — cosmetic ring + bumps defense target-scoring weight for ~5s.            | Soft: only raises weight, does not override cloak/range/engagement rules. |
| Workers (field)                           | **Click to inspect** — popover with current task, HP, modifiers; "send home" soft suggestion button. | Soft: cancels current target, worker picks next per AI.                   |
| City core                                 | **Click to inspect** — popover with HP/regen/energy breakdown. No abilities.                         | Read-only.                                                                |
| Resource pills (header)                   | Already there; leave as-is.                                                                          | —                                                                         |
| Speed / admin / achievements              | Already there; leave as-is.                                                                          | —                                                                         |

Everything stays **click-level only** — no drag, no hotkeys beyond existing ones, no touch gestures. This keeps the interaction model consistent with existing click-for-achievement affordances and keeps mobile parity trivial.

## 2. Work breakdown

### 2.1 Purchase flow (biggest slice)

- New `src/game/purchases.ts` module exporting `purchaseUpgrade(state, key): { ok: boolean; reason?: string }`. Extract the cost-check + `deductUpgradeCost` + level-increment + log lines from [autobuy.ts:203](src/game/subsystems/autobuy.ts) so both manual and auto paths share one code path.
- `GameState` gains `upgradeAutoFlags: Partial<Record<UpgradeKey, boolean>>` and `upgradeAutoMaster: "all" | "none" | "custom"`. Save/migrate per the checklist in AGENTS.md (§Save State And Migration): add to `types.ts`, default in `factories.ts`, defensive `?? {}` / `?? "all"` in `migrateGameState` so **existing saves default to autobuy-on** (identity preservation), deep-copy in `cloneGameState`.
- `stepAutobuy()` changes: before selecting a candidate, filter out upgrades whose flag resolves to `false` under the master setting. Master `"all"` → always auto; `"none"` → never auto; `"custom"` → per-flag. Emergency path still respects flags (the player opted out deliberately).
- `UpgradeTile` in [src/components/HudPrimitives.tsx:76](src/components/HudPrimitives.tsx) gets: a clickable button state when affordable + gate passed, a tooltip reason when not, a small Auto toggle chip. Disabled state + reason uses existing tone vocabulary (§HUD And Indicator Conventions).
- Sidebar upgrade panel header gets the master Auto switch (All / None / Custom).
- Log category: reuse `"upgrade"`; purchase messages distinguish `"auto"` vs `"manual"` origin.
- Achievement hooks: add `first_manual_purchase`, `autobuy_off_milestone` (survive X ticks without autobuy), `full_manual_run` (reach tier 3 with master=none). Follow §Achievement System Invariants exactly.

### 2.2 Worker suggestion layer

- Add `agent.suggestedTarget?: { kind: "node" | "enemy" | "home"; id?: string; expiresAt: number }` to `Agent` in types.ts. Migration: `?? undefined`. Clone: shallow spread works (primitive-ish object).
- `chooseWorkerTarget()` gets a soft preference: if `suggestedTarget` is set, unexpired, and the target passes the existing safety/eligibility filters, pick it. Otherwise, fall back to normal scoring and clear the suggestion. **Do not bypass the path-threat / corruption / flee rules** (§Worker Harvesting Stubbornness, §Worker Flee-Retarget Invariant).
- New helper in `src/game/interactions.ts` (new file): `suggestWorkerToNode(state, nodeId, clickXY)` — finds nearest idle/eligible worker, stamps its `suggestedTarget`, expires in ~120 ticks. Also `suggestDefensePriority(state, enemyId)` — adds an entry to a short-lived `state.priorityMarks: { enemyId, expiresAt }[]` list that defense target-scoring reads with a +weight bias.
- `FieldSvg.tsx` click handlers: extend the existing click routing (tourists, corpses, projectiles) to include nodes, enemies, and the city. Hit-testing reuses the existing radius + z-order walk — keep the achievement clicks winning ties where they already do.
- Visual feedback: a brief pulse ring on the clicked target, per §Coarse-Pointer Desktop FX Budget — the effect must simplify under `useLowFxMode`, not disappear.

### 2.3 Inspect popovers

- New `FieldPopover` component — fixed-positioned, viewport-anchored per §HUD And Indicator Conventions (tooltip pattern). One popover at a time.
- Worker popover: task, HP bar, speedMod/fearMod chips, "Send home" button (sets `suggestedTarget: home`, 60-tick expiry).
- City popover: hp / maxHp / regen / lastHostileTick / energy factor. Purely informational.
- Enemy popover: kind, hp, shield, threat, cloak state, "Mark priority" button.

### 2.4 Onboarding + idle-mode continuity

- First-run overlay (persisted via existing schema): one card explaining "Click upgrades to buy. Or flip Auto on and watch." Dismissible; stored as `state.meta.v4OnboardingSeen: boolean`.
- Loaded saves skip the overlay automatically (`upgradeAutoMaster` already `"all"` from migration).
- `handoff.md`, `README.md`, `AGENTS.md`, `src/changelog.ts`: full release pass per §Release Work Checklist. Bump `package.json` to `4.0.0`, run `npm install` for lockfile, bump `SCHEMA_VERSION`.

### 2.5 Tests (add in same commits as features)

- `purchaseUpgrade` unit tests: success, insufficient resources, tier-gated, already at max level.
- Autobuy respects flags: `master="none"` → no purchases across N ticks; `"custom"` with one flag off → that upgrade never bought, others still bought.
- Migration test: 3.1.4 save → 4.0 comes up with `upgradeAutoMaster === "all"` and no regression in existing round-trip tests.
- Worker suggestion: honored when safe; rejected when path threat present; cleared on arrival or expiry; flee rules still win (§Worker Flee-Retarget Invariant test extended).
- Defense priority mark: raises target score but does not override cloak filter (§Enemy Target Eligibility).
- Update test-count references in README/AGENTS/handoff in the same pass (§Test Count References).

## 4. Phasing (within the 4.0 release)

Suggest landing in **three commits on a single branch**, not a staged multi-release:

1. **Purchase flow + autobuy-flag refactor + migration** (biggest, highest-risk slice — ship + verify alone).
2. **Worker suggestion + priority marks** (self-contained, behind existing click router).
3. **Popovers, onboarding, docs, version bump, changelog.**

This keeps any regression surface isolatable via `git bisect` and keeps the changelog coherent.
